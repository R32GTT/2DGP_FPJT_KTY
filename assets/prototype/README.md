# 요청 에셋 — 그림 기반 최소 목업

아래 경로에 PNG를 넣고 목업을 다시 실행하면 자동으로 불러온다.
원본 이미지는 배치 타일로 변환하지 않고, 장면 JSON의 미터 단위 영역에 그대로 그린다.
지금은 이미지가 없는 부분을 도형·기존 바닥 이미지로 표시한다.

## 먼저 필요한 파일

| 파일 | 권장 원본 크기 | 실제 영역·요청 내용 |
| --- | --- | --- |
| `terrain.png` | 2304×1536px | 전체 36×24m 바닥. 건물·차량·인물을 그리지 않은 잔디/흙 배경 |
| `facility_floor.png` | 768×512px | 12×8m 창고 바닥. 이미지 좌상단은 월드 (-6,-4)m |
| `facility_walls.png` | 768×512px, 투명 PNG | 위 바닥과 정확히 같은 캔버스·정렬의 외벽. 내부·문 구멍은 투명 |
| `player.png` | 192×96px 이상 권장 | 단일 프레임 수직 탑다운 인물, 투명 배경, 중심 기준, 오른쪽 바라보기 |
| `guard.png` | 위와 같은 규격 | 플레이어와 구별 가능한 단일 프레임 경비 |

플레이어·경비 그림은 0.75×0.375m로 표시한다. 캐릭터 캔버스와 몸체 판정은 독립이다.
애니메이션·무기·사격 효과는 첫 에셋에 포함하지 않아도 된다.
그림을 기존 비율과 다르게 제공할 때는 원하는 실제 크기·기준점도 함께 알려주면 된다.

## 현재 시설 그림의 정렬 기준

벽 두께는 목업 데이터의 임시값인 0.25m, 위 권장 캔버스에서 16px다.
외벽은 캔버스 가장자리의 북·서·동 벽과 남쪽 벽이며,
남쪽 중앙에 폭 1.8m의 문 구멍을 둔다. 권장 원본 기준 구멍은 대략 x=326~442px다.
문짝은 `facility_walls.png`에 굽지 않는다. 실행기가 문 상태에 맞춰 따로 표시한다.
픽셀 수는 제작 참고값이며 판정 데이터의 원본 단위는 미터다.

시설 내부의 엄폐물·노란 보급 상자는 현재 실행기가 별도 도형으로 그린다.
다른 평면도를 주면 `prototype/scenarios/image_yard.json`의 벽·출입구·이동 경로를
그 그림에 맞춰 별도로 매핑해야 한다. 그림 색을 자동으로 충돌로 해석하지 않는다.

## 선택적으로 교체할 파일

- `road.png`: 36×2m, 권장 2304×128px. 전체 배경에서 분리된 길 오버레이.
- `dirt_patch.png`: 9×7m, 권장 576×448px. 투명 가장자리의 흙 패치.
- `door.png`: 닫힌 가로 문. 표시 영역 1.8×0.25m. 원본 크기는 자유.

`terrain.png`에서 길을 직접 그리려면 장면 JSON의 `road` 레이어를 제거해 중복 표시를 피한다.
현재 장면은 월드 좌상단 (-18,-12)m, Y축 아래 방향이며 각 레이어 위치와 실제 크기는 JSON에서 조정한다.
