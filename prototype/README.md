# 그림 기반 최소 플레이 목업

이미지 레이어·미터 좌표·줌·공간 조회·기초 AI를 확인하기 위한 단일 시설 목업이다.
`PlayPrototype.bat`를 더블클릭한다. 처음 실행할 때는 다음 환경이 필요하다.

```powershell
py -3.13 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r prototype/requirements.txt
& .\.venv\Scripts\python.exe -B -X utf8 -m prototype
```

이번 작업에서 프로젝트 가상환경과 Pico2D를 준비했다. 가상환경은 Git에 포함하지 않는다.
새 PNG가 없어도 기존 바닥 이미지와 색상·도형 표현으로 실행된다.
필요한 그림의 파일명·크기는 [assets/prototype/README.md](../assets/prototype/README.md)를 따른다.

## 조작

| 입력 | 동작 |
| --- | --- |
| WASD | 이동, 3m/s |
| Shift + 이동 | 달리기, 5m/s |
| 마우스 | 조준 |
| 좌클릭·길게 누르기 | 발사, 초당 약 6발 |
| 휠·`+`·`-` | 50~400% 줌 |
| F | 가까운 문 열기·닫기 |
| E | 노란 보급 상자에서 실제 캠페인 창고 물자 10개 확보 |
| P | 일시정지·재개 |
| F1 | 충돌 영역·AI 시선 표시 |
| Esc | 종료 |

카메라는 플레이어를 따라간다. 포커스를 잃으면 일시정지하며, P로 재개한다.
기준은 `1m=64px`이며 줌은 렌더링에만 적용한다. 캐릭터 그림의 표시 크기는
기준 줌에서 48×24px, 최대 줌에서 192×96px다. 몸체 판정은 별도 0.44×0.44m다.
실제 스케일·줌의 적절성은 사용자가 직접 플레이하며 확인한다.

## 현재 범위

- 36×24m의 작은 영역, 이미지 오버레이와 별도 미터 단위 직사각형 충돌.
- 문 개폐, 벽 미끄러짐, 탄환 이동 선분의 가장 가까운 충돌 판정.
- 훈련용 로컬 경비 2명: 순찰, 거리·시야각·벽 차폐 확인, 마지막 관측 위치 추격.
- 내비게이션은 그림 위에 지정한 노드와 희소 연결이다. 타일맵을 생성하지 않는다.
- 기존 `campaign`의 `Position`, 지도 좌표 변환, `Simulation`과 자원 회계를 재사용한다.
- 캠페인은 1초 단위로 진행한다. 상자 상호작용은 `depot_a` 재고에서 실제 차감되고
  캠페인의 플레이어 확보분에 기록된다.

로컬 경비는 AI 실험용 개체다. 군수 부대의 병력·차량과 연결하는 근원거리 전환은 후속 작업이다.
경비는 플레이어를 추격하며 반격은 하지 않는다. 로컬 플레이 상태는 이번 목업에서 저장하지 않는다.
벽 파괴 마스크·이미지 매핑 에디터·대형 월드 생성은 이 목업의 완성 범위가 아니다.

## 모듈 경계

| 파일 | 책임 |
| --- | --- |
| `world.py` / `scenarios/image_yard.json` | 이미지 레이어·독립 판정·실제 크기·배치 데이터 |
| `geometry.py` | 단순 충돌, 공간 해시, 셀 순회 ray 조회 |
| `navigation.py` | 수작업 희소 그래프 경로와 문 상태 반영 |
| `actors.py` / `movement.py` | 로컬 상태와 고정 틱 몸체 이동 |
| `ai.py` | 순찰·관측·기억·이동 의도. SDL과 그리기에 의존하지 않음 |
| `combat.py` | 발사 주기·탄환 수명·선분 충돌 |
| `bridge.py` | 기존 군수 시뮬레이션과 창고 회계 연결 |
| `simulation.py` | 고정 틱 실행과 상호작용 조합 |
| `camera.py` / `rendering.py` | 좌표 변환·PNG·임시 도형·캐시된 HUD |
| `controls.py` / `__main__.py` | 입력과 실행 루프 |

## 성능 설계와 수동 확인

이미지는 시작 시 한 번 로드하고 발사 시 리소스 I/O를 하지 않는다.
그림 레이어는 화면과 겹치는 것만 표시한다. 줌은 텍스처 재생성 없이 GPU 크기 변환을 사용한다.
HUD는 텍스처를 캐시하며 표시 내용은 초당 5회 갱신한다.
벽 조회는 ray가 지나간 공간 해시 셀의 후보만 검사한다. 문은 해당 콜라이더 상태만 변경한다.
AI 관측은 0.15초 간격으로 분산하고, 경로 요청은 0.6초 간격·고정 틱당 최대 하나로 제한한다.
탄환은 수명 1초·최대 128개이며, 몸체 이동은 60Hz 고정 틱이다.
프레임 지연은 최대 0.1초·6틱만 반영하는 로컬 검증 루프다. HUD 시간은 게임 로직의 재현성과 별개다.

일반 플레이·성능 평가는 사용자가 수행한다. 이번 작업에서는 필수 시작·핵심 판정만 확인한다.
짧은 코어 실행과 창 시작 확인 명령:

```powershell
py -3.13 -B -X utf8 -m prototype --headless --frames 180
& .\.venv\Scripts\python.exe -B -X utf8 -m prototype --frames 90
```

플레이 중 줌을 바꿔도 문 통과 폭·이동 속도가 같은지, 문 뒤 경비가 벽 너머를 보는지,
벽을 향한 연사가 끊김을 만드는지 확인하면 된다. HUD의 갱신·그리기 시간은 국소 참고값이며
전체 게임의 최악 상황 성능을 보장하는 수치가 아니다.
